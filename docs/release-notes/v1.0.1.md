**ocr 1.0.1: prebuilt Linux binary, and Bates and loop-retry fixes.** Start with [docs/TESTERS.md](https://github.com/pkeenan87/ocr/blob/v1.0.1/docs/TESTERS.md).

**Download**
- **Linux x86-64:** `ocr-1.0.1-linux-x86_64.tar.gz` contains:
  - the `ocr` binary (glibc 2.35 or later: Ubuntu 22.04, Debian 12, Fedora 36 and newer);
  - the Claude skill (`skills/ocr`);
  - the README and the tester guide;
  - the license and THIRD_PARTY_NOTICES.md.

  Check it with the `.sha256` file beside it.
- **Mac:** the [1.0.0 binary](https://github.com/pkeenan87/ocr/releases/tag/v1.0.0) still applies, or build 1.0.1 from source. The Mac-relevant change is the loop retry below.
- **Windows:** still a preview, not yet run on a real machine.

**Getting started on Linux:**

    sha256sum -c ocr-1.0.1-linux-x86_64.tar.gz.sha256
    tar xzf ocr-1.0.1-linux-x86_64.tar.gz
    sudo cp ocr-1.0.1-linux-x86_64/ocr /usr/local/bin/
    ocr server setup --model dots-ocr
    ocr server start --model dots-ocr
    ocr scan --model dots-ocr --input-file filing.pdf

Setup picks the CUDA, Vulkan or CPU build of llama.cpp for your hardware, and downloads it with pdfium and the model weights. Every file is checked against a pinned sha256.

**Fixes**
- **Bates numbers off the Mac:**
  - **Centred stamps.** A Bates number centred under the footer is now read, through a third request at the bottom centre of the page.
  - **Numbers in body text.** A number inside a body sentence is no longer taken as the Bates number when the model drops the footer. This mistake also stopped the corner request that would have read the real stamp.
  - **Sideways pages.** olmOCR now reads the Bates corners from the turned page.
  - **Results on synthetic pleadings:** Bates accuracy went from 9/11 to 11/11 for olmOCR and from 10/11 to 11/11 for dots. On the first 100 pages of a synthetic production, dots went from 90% to 100%. On a test document with centred stamps, all three engines read 4/4.
- **Loop retry:**
  - **Penalty ignored off the Mac.** The repetition penalty is now sent as llama-server's `repeat_penalty`. The old field name was silently ignored, so a looping page was retried unchanged.
  - **Cut-off loops (all platforms).** A loop that runs into the token limit now gets the penalty retry instead of more tokens. Such loops are recognised even when the repeated line has few letters (`By _____`) or counts up (`[801] …`, `[802] …`).
  - **Results:** on 230 pages of real court filings, Paddle on Linux had lost 3 pages to this; now it loses 1. On the Mac a cut-off loop now gets the penalty before the Apple fallback; this path has not been run on a Mac yet.

**Use `dots-ocr` on Linux.** `paddleocr-vl`, the default, is the fastest, but without Apple Vision's table crops it is weak on tables and transcripts.

**Under the hood**
- **Release workflow.** The Linux binary is built on ubuntu-22.04 by a release workflow, with third-party notices.
- **Tests.** The model-engine tests now run on Linux and Windows in CI, in release mode. These are the off-Mac pipeline, Bates corner requests, resume, `--jobs` and the server lock.

**Upgrading:** the `ocr` version is part of each output's `scan_record`. In directory mode, outputs made by an earlier version are rescanned once.

**Known limits on Linux:**
- No Apple Vision:
  - transcripts are not detected, and their line numbers are not re-anchored;
  - values on scanned pages are never `verified`.
- On a page stored sideways, `dots-ocr` finds no Bates number (`olmocr` does).
- On a page whose footer the model dropped, a number that ends a body sentence (`…Invoice No. INV-24337.`) can still be taken as the Bates number.

The full list is in the [README](https://github.com/pkeenan87/ocr/blob/v1.0.1/README.md#known-limits).

**Please report** any value marked `verified` that is wrong. That is the failure that matters most.
